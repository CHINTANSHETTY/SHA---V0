# Verification Protocol & Reproducibility Checklist

This document provides a systematic verification protocol to independently validate all experimental claims and artifact outputs of the **KDR-CA-AEAD** framework.

---

## 1. Repository Integrity & Hash Verification

Verify the integrity of clean repository checkouts using Git commit signatures or SHA-256 hashes:

```bash
git log -1 --stat
```

Expected branch: `main` or tagged release `v1.0.0`.

---

## 2. Automated Test Verification

Execute the test suite to confirm operational zero-error status:

```bash
pytest tests/
```

- Expected outcome: `=== 465 passed in X.XXs ===`
- Zero `FAILED`, zero `ERROR`.

---

## 3. Benchmark Verification Protocol

To reproduce performance benchmark data:

```bash
python crypto/benchmarking/benchmark_report.py
```

Check output directory `reports/`:
1. `reports/benchmark_summary.md` generated.
2. SAC ratio falls strictly within $[49.5\%, 50.5\%]$.
3. Throughput metrics logged for sizes 64B, 1KB, 64KB, 1MB, 10MB.

---

## 4. Hash & Output Verification

Verify reproducible execution logs and artifact hashes generated by `run_phase2_5_reproducibility.py`:

```bash
python run_phase2_5_reproducibility.py
```

Verify that the output hash log matches baseline entries in `reports/reproducibility_manifest.json`.

---

## 5. Reproducibility Checklist

- [x] All source code files clean without uncommitted local edits.
- [x] Python dependencies pinned in `requirements.txt`.
- [x] Test suite passing 100%.
- [x] Benchmark execution completes without memory leaks or uncaught exceptions.
- [x] Formally verified constant-time HMAC tag comparison.
- [x] Generated reports match published tables and figures in paper manuscript.
