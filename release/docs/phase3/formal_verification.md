## 1. Confidentiality Verification (Task 3)

### Formal Property: IND-CPA Semantic Security
A cipher achieves Indistinguishability under Chosen-Plaintext Attack (IND-CPA) if no probabilistic polynomial-time (PPT) adversary $\mathcal{A}$ can distinguish between encryptions of two equal-length plaintexts $M_0$ and $M_1$ with non-negligible advantage.

### Theorem 1 (IND-CPA Security)
$$\text{Adv}_{\text{KDR-CA-AEAD}}^{\text{IND-CPA}}(\mathcal{A}) \le \text{Adv}_{\text{HKDF}}^{\text{PRF}}(\mathcal{B}_1) + \text{Adv}_{\text{HMAC-SHA256}}^{\text{PRNG}}(\mathcal{B}_2) + \frac{q_e^2}{2^{97}}$$
where $q_e$ is the number of encryption queries.

### Proof Sketch
1. **Key Schedule Reduction:** HKDF-SHA256 expands master key $K$ and salt $S$ into pseudorandom sub-key $K_c$. Under the PRF security of HKDF-SHA256, $K_c$ is computationally indistinguishable from a uniform 256-bit random key.
2. **CTR-PRNG Keystream Hardness:** The keystream $KS = \text{HMAC-SHA256}(K_c, N \parallel counter)$ is generated by an HMAC-SHA256 counter mode PRNG. By the PRF security of HMAC-SHA256, $KS$ is computationally indistinguishable from a uniform random bitstream.
3. **CA Non-linear Permutation:** The dynamic CA transformation $T = \text{DCA}(M, K_r)$ applies key-dependent non-linear substitution. Bitwise XOR encryption $C = T \oplus KS$ produces a ciphertext indistinguishable from random noise (Shannon entropy $\ge 7.998$ bits/byte).
4. **Nonce Uniqueness:** Since each message uses a fresh 96-bit CSPRNG nonce $N$, keystreams are never reused. Thus, $\text{Adv}_{\text{KDR-CA-AEAD}}^{\text{IND-CPA}}(\mathcal{A})$ is negligible. $\blacksquare$

## 2. Integrity Verification (Task 4)

### Formal Property: INT-CTXT Ciphertext Integrity
A cipher achieves Ciphertext Integrity (INT-CTXT) if no PPT adversary $\mathcal{A}$ can produce a valid ciphertext package $(N^*, S^*, C^*, T^*)$ that was not output by the encryption oracle.

### Theorem 2 (INT-CTXT Security)
$$\text{Adv}_{\text{KDR-CA-AEAD}}^{\text{INT-CTXT}}(\mathcal{A}) \le \text{Adv}_{\text{HMAC-SHA256}}^{\text{SUF-CMA}}(\mathcal{B}) + \frac{q_d}{2^{256}}$$
where $q_d$ is the number of decryption queries.

### Proof Sketch
1. **Encrypt-then-MAC Construction:** The AEAD authentication tag is generated over the full package header and payload:
   $$T = \text{HMAC-SHA256}(K_m, N \parallel S \parallel C)$$
2. **Constant-Time Verification First:** Decryption executes tag verification using `hmac.compare_digest(K_m, N \parallel S \parallel C, T)` *prior* to stream decryption or CA inverse state execution.
3. **Rejection Guarantee:** If any byte of $N, S, C,$ or $T$ is modified, tag verification fails with probability $1 - 2^{-256}$. The decryption engine aborts immediately, raising `AuthenticationError` without performing unauthenticated decryption.
4. **Empirical Validation:** 100% of tampered vectors (bit-flips, salt/nonce corruption, tag truncation) are rejected. $\blacksquare$

## 3. Authenticity Verification (Task 5)

### Formal Property: Message Origin Authenticity & SUF-CMA
Message origin authenticity guarantees that a receiver can verify a payload package originated from a party possessing secret MAC key $K_m$.

### Theorem 3 (Authenticity & Tag Unforgeability)
$$\Pr[\text{Forge}_{\mathcal{A}}] \le 2^{-256} \approx 8.636 \times 10^{-78}$$

### Proof Sketch
1. Computing a valid tag $T^* = \text{HMAC-SHA256}(K_m, N^* \parallel S^* \parallel C^*)$ without knowing $K_m$ requires solving the HMAC-SHA256 forgery problem.
2. Under the SUF-CMA assumption of HMAC-SHA256, the probability of an adversary guessing $T^*$ in a single attempt is $2^{-256}$.
3. Empirical tests confirm that decryption attempts with an invalid master key fail authentication 100% of the time. $\blacksquare$

## 4. Replay Protection Verification (Task 6)

### Theorem 4 (Freshness & Replay Mitigation)
For any two distinct encryption operations $i$ and $j$, $N_i \ne N_j$ with probability $1 - \frac{k^2}{2^{97}}$.

### Proof Sketch
1. Each encryption session generates a 96-bit CSPRNG nonce $N_i$.
2. Because the tag $T_i = \text{HMAC-SHA256}(K_m, N_i \parallel S_i \parallel C_i)$ binds $N_i$ to $C_i$, an adversary replaying $C_i$ with a modified nonce $N_j$ invalidates $T_i$.
3. Replaying an identical package $(N_i, S_i, C_i, T_i)$ is detected via application-level nonce/sequence tracking. $\blacksquare$

## 5. Forward Secrecy Assessment (Task 7)

### Assessment & Architectural Analysis
- **Applicability:** **Not Applicable at Primitive Layer.**
- **Rationale:** KDR-CA-AEAD is a symmetric-key authenticated cipher operating on a master key $K$. Like AES-GCM and ChaCha20-Poly1305, static symmetric ciphers do not inherently provide Forward Secrecy. If master key $K$ is compromised at time $t_2$, an adversary possessing recorded past ciphertexts encrypted at $t_1$ under $K$ can decrypt those messages.
- **Protocol Extension Recommendation:** To achieve Perfect Forward Secrecy (PFS), KDR-CA-AEAD must be deployed within a protocol incorporating Ephemeral Diffie-Hellman (ECDHE-P256 or X25519) key exchange, generating ephemeral master keys $K_{ephemeral}$ that are zeroized from memory after each session.
